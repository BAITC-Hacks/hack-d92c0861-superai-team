# Career Quest

Career Quest помогает сотруднику увидеть путь к выбранной роли или следующему грейду. Приложение сопоставляет навыки с требованиями цели, предлагает до трёх доступных развивающих активностей и объясняет выбор фактами. HR видит общие разрывы навыков и сотрудников, для которых в каталоге пока нет подходящего шага.

Проект создан для кейса Halyk Bank на HackAlem AI. Профили в предоставленном датасете синтетические.

## Состояние проекта

В текущем `main` работает серверная часть: профиль, расчёт навыков и прогресса, рекомендации, завершение активности, импорт новых профилей и истории, HR-сводка и локальное сохранение состояния. Ответы API и права доступа проверяются на сервере.

Интерфейс в `main` пока является проверочной оболочкой и показывает ответ как JSON. Новый интерфейс Саята подготовлен в `sayat-front/frontend/`, но ещё не перенесён в `main`. Расширенный AI Михаила также не интегрирован. По умолчанию рекомендации выдаёт прозрачный резервный алгоритм; живой LLM-вызов общей версии пока не подтверждён. **Текущий `main` ещё не окончательный MVP.**

## Что реализовано

| Возможность | Работающий результат |
| --- | --- |
| Профиль и траектория | Роль, грейд, история, фактические навыки, карьерная цель и покрытие требований цели. |
| Рекомендации | До трёх доступных шагов с объяснением по цели/грейду, разрывам навыков, истории участия и формату. Если шага нет, показана причина. |
| Завершение активности | Прирост ограничен `gain` и `max_level`; повторный запрос не начисляет его второй раз. |
| Импорт жюри | HR загружает дополнительные `employees.json` и/или `activity_history.csv`. Ошибка отклоняет весь импорт. |
| HR-сводка | Частые разрывы, сотрудники без подходящего шага и участие по статусам. |
| Доступ | Сотрудник видит только свой профиль, HR — сотрудников, импорт и сводку. |

Процент прогресса означает **покрытие требований по навыкам**, а не вероятность повышения. Прогноз каждого шага рассчитан от текущего состояния отдельно; прогнозы разных карточек не складываются.

## Как устроено решение

```text
Vue 3 + Vite (frontend/)
        │ HTTP / JSON
        ▼
FastAPI (backend/main.py)
        ├── data_loader.py, domain.py — данные и проверяемые расчёты
        ├── storage.py — SQLite, импорт и выполнение
        ├── reporting.py — HR-сводка
        └── ai/engine.py → ai/provider.py — выбор шагов и необязательный LLM
```

Общие формы запросов и ответов находятся в `shared/contracts.py`; маршруты описаны в [API-контракте](docs/API_CONTRACT.md). Численные уровни, допустимость активности и прирост вычисляет Python-код. LLM, когда включена, выбирает только из проверенных кандидатов. При сбое провайдера система явно обозначает режим `fallback`.

Технологии текущего `main`: Python 3.11+, FastAPI, Pydantic, SQLite из стандартной библиотеки, HTTPX, Vue 3, Vite, JavaScript и JSON/CSV. Отдельного AI-сервера, Redis и векторной базы нет. Провайдер LLM настраивается через совместимый с chat completions API; конкретная модель не зашита в код.

## Данные

Стартовый набор: **200 сотрудников, 40 активностей, 60 навыков, 32 матрицы требований и 2 743 записи истории**. Источник — `career_quest_dataset.zip` от организаторов. Модельная дата набора — **2026-10-01**; приложение берёт её из `meta.as_of_date`, а не из часов компьютера.

`employees.skills` — результат последней оценки. Завершения после `last_review_date` добавляются по правилам активностей; более ранняя история не начисляется повторно. Исходные JSON/CSV не изменяются: новые действия хранятся в локальной SQLite. Три собственных неоднозначных сценария находятся в [docs/jury_examples](docs/jury_examples/README.md); это не скрытые профили жюри.

Официальный ZIP, распакованные файлы, `.env`, база SQLite и ключи не входят в Git. Для воспроизведения жюри нужен стартовый ZIP через платформу хакатона или другой разрешённый организаторами способ передачи. **Без данных сервер не запустится.**

## Установка и запуск

Нужны Python 3.11+, Node.js 22.12+ и npm. Команды выполняются из корня репозитория. Первый запуск на Windows PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe scripts\seed_data.py "C:\путь\к\career_quest_dataset.zip"
.\.venv\Scripts\python.exe scripts\setup_env.py
npm --prefix frontend install
npm --prefix frontend run build
.\.venv\Scripts\python.exe run.py
```

Откройте **http://127.0.0.1:8000**; документация API — **http://127.0.0.1:8000/docs**. Для разработки после установки зависимостей запустите `.\.venv\Scripts\python.exe run.py --dev`: интерфейс будет на порту 5173, API — на 8000. В Linux/macOS используйте `python3 -m venv .venv` и `./.venv/bin/python` вместо Windows-пути к Python.

`seed_data.py` и `setup_env.py` не перезаписывают существующие файлы. Если данные и `.env` уже подготовлены, пропустите эти два шага. Локальный `.env` содержит разные `EMPLOYEE_TOKEN` и `HR_TOKEN`; не отправляйте их в Git или чат. Путь к состоянию задаётся `STATE_PATH`, по умолчанию `.local/career_quest.sqlite3`.

### Настоящая LLM

Для живого выбора модели укажите **только в серверном `.env`**:

```dotenv
AI_ENABLED=true
LLM_BASE_URL=https://<разрешённый-провайдер>/v1
LLM_MODEL=<модель>
LLM_API_KEY=<локальный-ключ>
```

Провайдер должен поддерживать совместимый `/chat/completions`. Ключ не должен находиться в `frontend/`, переменных `VITE_*` или истории Git. Без этих настроек приложение запускается, но честно помечает рекомендации как `fallback`. Перед отправкой контекста внешнему сервису команда должна использовать разрешённый организаторами endpoint.

## Как проверить решение

1. Запустите приложение с официальным ZIP и войдите с локальным `EMPLOYEE_TOKEN`.
2. Откройте профиль `E0001`: проверьте цель, разрывы навыков, историю и причины рекомендованных шагов. Текущий интерфейс `main` показывает данные в JSON.
3. Через Swagger на `/docs` отметьте доступную `self_paced` активность выполненной. Повторите тот же запрос с тем же `idempotency_key`: второго прироста быть не должно. После перезапуска результат сохраняется.
4. Войдите с `HR_TOKEN`. Загрузите [собственные проверочные профили и историю](docs/jury_examples/README.md) через `POST /api/admin/import`, откройте новый ID и `GET /api/hr/overview`. Испорченный CSV должен вернуть ошибку без частичного импорта.
5. Если LLM настроена, проверьте `mode=llm` и время ответа; иначе — `mode=fallback` и явную причину.

Автоматические проверки текущего `main`:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe scripts\check_dataset.py
.\.venv\Scripts\python.exe scripts\check_backend.py
npm --prefix frontend run build
```

Последняя проверка backend: **76 тестов прошли**; проверка полного датасета и сквозного API с временной SQLite прошла в режиме `fallback`. Для интерфейса в ветке Саята отдельно прошли **41 клиентский тест** и production-сборка. Это не заменяет общий браузерный проход после интеграции.

## Известные ограничения

- Новый интерфейс Саята и расширенный AI Михаила пока не находятся в `main`; их нельзя считать частью общей сборки.
- Живой LLM-вызов, ручной браузерный сценарий и полная задержка «клик → рекомендация» не подтверждены.
- Авторизация через demo-токены предназначена для локального показа, не заменяет банковский SSO.
- В исходном CSV нет точного времени завершения `self_paced` активности. Для исторического пересчёта используется доступное поле `date`; новые завершения сохраняют отдельное `completed_at`.
- Не каждый профиль имеет подходящее событие в каталоге. Система сообщает об этом вместо выдуманной рекомендации.
- Развёрнутой публичной версии пока нет.

Перед сдачей обновите этот README по фактически объединённому `main`, проведите браузерный сценарий и проверьте запуск из чистого клона. План работы команды — в [docs/START_HERE.md](docs/START_HERE.md).
