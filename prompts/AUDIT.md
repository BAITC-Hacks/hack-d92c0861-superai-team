# Промпт архитектурного аудита на контрольной точке

Проведи аудит приложенного текущего кода Career Quest по CONTEXT.md и исходному ТЗ.
Не оценивай реализацию по отчётам Codex без проверки файлов. Я прикладываю архив исходников
без .env, ключей, .venv, node_modules и runtime-персональных данных, diff и результаты тестов.

Контрольная точка: <1/4, 2/4, 3/4 или 4/4>. Осталось времени: <сколько осталось>.
Сверь: реальный UI→API→AI вызов; схемы; все must-have; импорт новых IDs; last_review/as_of;
gain/max_level; critical и prerequisites; idempotency/restart; история/доступы; честность fallback;
README/one-command run; ошибки/latency. Запускай доступные тесты, не утверждай, что запустил невозможные.

Ответ дай как verdict по каждому пункту: PASS / FAIL / NOT_IMPLEMENTED / NOT_VERIFIED.
Раздели P0 (ломает защиту), P1 (важная корректность), P2 (улучшения).
Для каждой ошибки укажи файл/функцию, минимальный патч или точное задание, владельца и acceptance-test.
Не переписывай весь проект, не добавляй новые технологии и optional-фичи.
В конце — следующие конкретные действия для Дамира, Саята и Михаила, без обещаний гарантированной победы.
