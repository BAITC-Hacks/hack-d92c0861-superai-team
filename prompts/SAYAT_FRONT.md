# Задание Codex: Саят / frontend

Ты работаешь в существующем Career Quest, ветка sayat-front. Прочитай AGENTS.md, CONTEXT.md,
README.md, docs/API_CONTRACT.md, shared/contracts.py и docs/examples/.
Сначала git status и осмотр текущего frontend. Сохрани полезный уже написанный UI.
Меняй только frontend/**. Не меняй API URL, Python, формулы, event IDs и JSON-схему под свой интерфейс.
Стек уже Vue 3 + Vite. Не переходи на React/Streamlit, не добавляй сложный state manager.

## Приоритет 1: один законченный сценарий
Замени App.vue integration shell на понятный экран сотрудника на русском:
профиль (роль/грейд/стаж), цель, текущие навыки и требуемые уровни, critical gaps, покрытие требований,
история участия, 1–3 карточки следующих активностей. У каждой карточки показывай минимум
три factors: цель/грейд, численные разрывы, история; формат, время и прогноз конкретного шага.
Все числа бери из backend. Для progress используй effective_skills/trajectory, не employee.skills.
Подпись процента — «Покрытие требований», не «Шанс повышения».
Не складывай прогнозы разных карточек: они независимо рассчитаны от текущего состояния.
Кнопка завершения вызывает api.complete; UUID один на действие и сохраняется для retry.
По успеху перечитай profile/recommendations. Пока backend возвращает 501, покажи «ещё не реализовано»,
не рисуй ложный успех. Во время запроса блокируй повторный клик.

## Приоритет 2: HR и загрузка жюри
HR-only экран: частые skill gaps, доля среди требующих навык, кто без шага и почему,
участие в событиях по статусам. Никаких публичных рейтингов сотрудников.
Форма загрузки двух отдельных файлов: employees.json и activity_history.csv,
оба или любой один; FormData через готовый api.importFiles, не менять Content-Type вручную.
Показать результат/ошибку импорта; после успешного импорта перечитать список/HR/profile.
HR выбирает любого сотрудника. Employee видит только собственный профиль: использовать /api/auth/me.
Не считать скрытие вкладки авторизацией — backend всё равно проверяет права.

## Приоритет 3: надёжность показа
Loading, timeout, пустой steps[], ошибки 401/403/409/422/501, перезапуск рекомендации.
mode=fallback видимым текстом «Резервный алгоритм, LLM недоступна/выключена».
При смене employeeId/выходе очищать предыдущие данные, защищаться от устаревшего ответа запроса.
Не отдавать ключи LLM браузеру. Demo token держать только в памяти; не публиковать в исходниках.
Не делать чат, платежи, награды, рейтинги, сложные анимации и регистрацию с паролем.
Сначала рабочий поток, затем внешний вид. Фикстуры из docs/examples — только для вёрстки,
mock mode должен быть явным и выключенным на демонстрации. Не подменяй реальные API незаметно.

## Готовность
Проверка npm --prefix frontend run build и ручной проход Employee/HR.
После npm install зафиксируй package-lock.json. Проверь one-command запуск.
Отчёт: изменённые файлы, какие endpoints реально подключены, build result, ограничения и оставшиеся 501.
Не делай merge/push самостоятельно и не меняй backend ради компиляции UI.
