# Career Quest — что делать сейчас

Этот файл описывает текущий checkout команды. Он важнее старых инструкций про отдельные ветки. Работайте в одной папке; каждый отвечает за свои файлы. Перед общим коммитом один человек проверяет весь сценарий.

## Что уже есть

- В `main` находится стартовый каркас: Vue в `frontend/`, FastAPI в `backend/`, AI в `ai/`, общий формат ответов в `shared/contracts.py`.
- Профиль, каталог и резервные рекомендации работают на сервере. Интерфейс пока выводит JSON.
- `POST /api/employees/{id}/complete`, `POST /api/admin/import` и `GET /api/hr/overview` пока возвращают 501. Значит, обязательный путь кейса ещё не готов.
- Более развитый AI находится в `origin/mikhail-ai`, а оформленный интерфейс — в `origin/sayat-front`. Они построены по другим схемам. Не сливайте эти ветки целиком в `main`: AI повторно читает файлы, а интерфейс считает рекомендации из встроенной копии датасета. Берите оттуда нужные алгоритмы, вёрстку и переводы, подключая их к действующему API.
- Исходный ZIP уже распакован локально в `docs/`; серверные demo-токены созданы в локальном `.env`. Эти файлы исключены из Git. Ключ LLM команда задаёт только локально.

## Один сквозной сценарий для защиты

HR или сотрудник открывает профиль → видит цель, навыки и 1–3 шага с конкретными причинами → отмечает подходящую активность выполненной → видит новый навык и процент покрытия → HR загружает проверочный профиль и историю → получает рекомендации для нового ID и сводку. Покажите отдельным примером честный резервный режим, если LLM недоступна.

`shared/contracts.py`, URL и формат JSON — общий договор. Один человек меняет их только после короткого согласования с двумя другими. Не копируйте целиком чужую ветку поверх каталога. В текущем общем каталоге не переключайте ветку во время работы коллег.

## Порядок проверки

1. Профиль и рекомендации идут через Vue → FastAPI → AI. Проверить произвольный ID.
2. Завершить доступное `self_paced` событие; навык и процент меняются. Повторный запрос ничего не начисляет. После перезапуска результат остаётся.
3. Загрузить новые `employees.json` и `activity_history.csv` через HR. Новый ID работает без перезапуска; ошибочный импорт не портит данные.
4. HR видит разрывы, сотрудников без подходящего шага и участие. Сотрудник не открывает чужой профиль.
5. Проверить сборку UI, серверные тесты, живой ответ LLM и запуск одной командой. После этого обновить README фактическим статусом.

Текущие сроки команды лучше считать от оставшегося времени, а не по фиксированным четвертям. Последние 20–30 минут оставить на запуск с чистой среды и репетицию, не на новые функции.

## Важные правила данных

Дата среза — `2026-10-01` из `meta.as_of_date`. `employees.skills` — последняя оценка, поэтому более старые завершения нельзя начислять снова. Прирост ограничен `gain` и `max_level`. Повторное прохождение обычно нельзя рекомендовать; исключение `EV_036`. Объяснение должно показывать цель/грейд, реальный разрыв и историю участия. Пропуски — факт истории, не характеристика человека.

В ZIP действительно присутствуют обычные `README.md`, `README.ru.md` и `README.kz.md`. Структурированные названия навыков и событий остаются на английском; перевод интерфейса — отдельная работа.
