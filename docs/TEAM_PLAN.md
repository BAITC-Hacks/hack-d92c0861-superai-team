# Три часа команды: четыре интеграционные точки

Это распределение оставшегося времени команды, не обещание длительности генерации кода.

| Интервал от старта | Общий критерий | Дамир | Саят | Михаил |
|---|---|---|---|---|
| 0–15 мин | Один контракт и запуск у всех | Подключить основу, проверить Swagger | Подключить Vue/API | Сохранить существующий ai, проверить adapter |
| 15–45 мин, 1/4 | Один реальный профиль + рекомендация | Начать durable state/completion | Профиль и карточка шага | Реальный provider и проверка IDs |
| 45–90 мин, 2/4 | Выполнение меняет профиль, повтор не начисляет | Completion + импорт | Кнопка, refresh, состояния | 3 спорных профиля, multi-factor |
| 90–135 мин, 3/4 | Импорт жюри + HR без перезапуска | Import rollback + HR + cache | Upload + HR | Ошибки provider и объяснения |
| 135–180 мин, 4/4 | Freeze, README, demo, полный smoke | Restart/auth/tests | Полировка и build | Live AI/demo story/latency |

Сливаем не по проценту строк, а по проверенному сценарию. Коммит чаще разрешён, интеграция не должна
ждать 45 минут, когда уже появился совместимый вертикальный кусок. Первую UI→API→AI проверку не откладывать.
После 135-й минуты не добавлять optional-фичи. Последний блок — на баги, повторяемость и демонстрацию.

## Работа с существующим репозиторием
Архив starter НЕ является текущим checkout команды. Сначала git status и резервный обычный коммит своей
чистой работы в своей ветке. Не использовать reset --hard, force push или копирование поверх ai/.
На integration-ветке сравнить существующие shared/API/ai interfaces. Выбрать одну схему и адаптировать
внутренности, а не держать две независимые реализации. Имя существующей ветки Михаила — mikhail-ai.
Если main защищён — Pull Request, не обход защиты.

Пример интегратора после того, как ветки отправлены и рабочее дерево чистое:
```powershell
git fetch origin
git switch main
git pull --ff-only origin main
git merge --no-ff origin/damir-back
python -m pytest -q
```
Остановиться при конфликте/падении. Не выполнять следующий merge, пока текущий не исправлен.
Затем по одному merge origin/mikhail-ai и origin/sayat-front, каждый с тестами; проверить frontend build.
Только после общего smoke-test: git push origin main. Один человек интегрирует, остальные не пушат main.

После обновления main каждый обновляет СВОЮ существующую ветку:
```powershell
git fetch origin
git switch mikhail-ai
git merge origin/main
```
Дамир/Саят подставляют свои ветки. Новую ветку создают от согласованного main только если её ещё нет.
Не создавать ветки заново после каждой интеграции. Не копировать целиком чужие папки.

## Чеклист демонстрации
1. HR выбирает сотрудника. Видны реальная цель/грейд, skill gap, critical и дата среза.
2. Показать 1–3 шага, минимум три проверяемых фактора и mode=llm при успешном настоящем вызове.
3. У подходящего сотрудника завершить доступную self_paced-активность, показать изменение навыка/процента.
4. Повторить запрос/клик — повторного gain нет. Перезапустить — результат сохранён.
5. Загрузить новые профили + CSV, выбрать новый ID без рестарта и получить новые рекомендации.
6. HR показывает competency gaps, отсутствующие шаги и участие; Employee не видит чужую историю.
7. Показать корректный fallback без выдачи его за LLM; неверный upload не ломает данные.

Оценивание ТЗ: работоспособность 25, техническая реализация 25, README/воспроизводимость 25,
ценность 15, потенциал/оригинальность 10. Поэтому документацию и запуск не откладывать на последнюю минуту.
