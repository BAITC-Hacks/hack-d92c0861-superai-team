# Career Quest — интегрированный интерфейс

Рабочий Vue-интерфейс общего проекта находится в `frontend/`. Оформление и часть переводов перенесены из `front-career-quest/`; старый проект не используется при сборке и не изменён. Изменения подготовлены для ревью, без commit/merge/push.

## Что подключено

Все запросы идут через существующий `src/api.js`, URL и серверный контракт сохранены.

| API | Экран/поведение |
| --- | --- |
| `GET /api/auth/me` | Вход, роль и собственный ID сотрудника |
| `GET /api/employees` | Выбор сотрудника только для HR, включая импортированные ID |
| `GET /api/employees/{id}` | Профиль, `effective_skills`, `trajectory`, история |
| `GET /api/employees/{id}/recommendations` | Шаги, все факторы, независимый прогноз каждого шага, явный `llm`/`fallback` |
| `GET /api/events`, `GET /api/skills` | Каталог и названия навыков |
| `POST /api/employees/{id}/complete` | Завершение реального участия; после успеха перечитываются профиль, рекомендации и HR |
| `GET /api/hr/overview` | Разрывы навыков, доля среди требующих навык, причины отсутствия шага, статусы участия |
| `POST /api/admin/import` | Два отдельных файла: employees JSON и history CSV; можно любой один или оба |

На клиенте нет расчётов навыков, прироста, покрытия требований или отбора рекомендаций. Числа берутся из ответов сервера; frontend только форматирует их и фильтрует отображение каталога. JSON/CSV исходного датасета не включены в `frontend/` и bundle. Контрактные примеры используются только тестами, режима с подменой API нет.

Токен, профиль и payload завершения находятся только в памяти вкладки. В localStorage сохраняется только язык. Один UUID создаётся на действие завершения; сетевой retry использует исходный UUID и тот же payload. Пока результат неизвестен, новые завершения, смена профиля и импорт блокируются. Для 409/422 требуется перечитать состояние и заново выбрать действие. Ответы предыдущей сессии/сотрудника отбрасываются, версии профиля и рекомендаций сверяются.

Будущую сессию нельзя отметить завершённой. Для начатого участия выбирается его ID; для повторяемого клуба требуется конкретное участие/наступившая сессия. Правила и права повторно проверяет backend.

## Запуск

Требуется Node.js **22.12+**, Python и зависимости из корневого `requirements.txt`. Сначала подготовьте локальные данные и серверный `.env` по инструкции корневого проекта; ключи и токены в исходники не добавляйте.

Из корня репозитория:

```sh
npm --prefix frontend ci
npm --prefix frontend run build
python run.py
```

Собранный интерфейс и API: `http://127.0.0.1:8000`.

Для разработки: `python run.py --dev`; Vue на `http://127.0.0.1:5173`, прокси `/api` на порт 8000. Используйте локальный токен Employee или HR. Закрытие/перезагрузка вкладки требует нового входа.

## Проверки

```sh
npm --prefix frontend test
npm --prefix frontend run build
```

41 автоматическая проверка: HTTP-адаптер, права и смена профиля, очистка сессии, устаревшие ответы, версии, retry completion, ошибки 401/403/408/409/422/501, импорт одного/двух файлов, рендеринг и локализация экранов Employee/HR.

Отдельный тест настоящего сервера (требуется свободный порт 8000):

```sh
DATA_DIR="/absolute/path/to/career_quest_dataset" CQ_PYTHON="/path/to/python" npm --prefix frontend run test:live
```

Он запускает `run.py` с временной SQLite и случайными токенами, отключает внешние AI-вызовы, проверяет собранный UI по HTTP, проходит Employee/HR через настоящий `api.js`/`session.js`, завершает активность и повторяет тот же запрос, импортирует контрольные профили, проверяет доступы и сохранение после перезапуска. Исходный датасет не изменяется, временный сервер и база удаляются после теста.

Проверено 23 сентября 2026: 41 тест и production build успешны; live smoke успешен. Пример серверного покрытия: 71.93 → 73.68%, повтор не начисляет прирост; импортированный ID доступен без перезапуска, невалидный импорт отклонён.

## Ограничения проверки

- Ручной проход в браузере не выполнен: инструмент не нашёл доступных браузеров. SSR-проверки и HTTP smoke не заменяют визуальную проверку, выбор файлов и клики в браузере.
- Живой LLM-провайдер не проверялся: сквозной тест использует явный `fallback`. Нужны разрешённый endpoint и локальный ключ команды.
- В проверенном сервере completion/import/HR уже реализованы; фактических 501 в live smoke нет. UI обрабатывает 501 без ложного успеха на старых/неготовых серверах.
- Токены — существующая demo-авторизация backend, не production SSO.
- В окружении проверки установлен Node 20.20.2: build/tests прошли, npm предупредил о требовании проекта Node 22.12+. Для команды используйте заявленную версию.
- Текущая ветка содержит старый `front-career-quest/` в истории. Для последующей интеграции переносите только изменения `frontend/`, не сливайте старую ветку целиком.
